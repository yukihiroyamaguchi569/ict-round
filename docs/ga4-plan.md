# GA4 学習・活用計画（めぐる君）

作成日: 2026-07-26

## 前提・方針

- めぐる君は「ダウンロードしたら電波が悪い場所でも使える」ことが売りのPWA。
- gtag.js にはオフライン時のイベント再送機能がなく、電波の悪い場所で発生したイベントは復旧後も送られず消失する。
  - 細かい行動（チェックリスト入力、写真追加など）のファネル計測は、電波の悪い場所ほどデータが欠けるため、離脱率のように見えてしまう危険がある。
  - アクティブユーザー計測も同様に過小カウントされるため、絶対数ではなく前週比・前月比のトレンドとして見る。
- 最初の目標は「細かいユーザー挙動の全計測」ではなく、**アクティブユーザーの把握と分析**。
- 点検者名・病棟名などの個人情報／医療現場の識別情報は絶対にGA4へ送らない（GA4利用規約にも抵触）。

## 重要な既知事象: 2026-06-17〜07-12 の計測データは無効

独自実装した `gtag` 関数が `dataLayer` に配列(`args`)を push していたため、gtag.js がコマンドとして認識できず、`config`/`event` が全て黙って破棄されていた（[fix: GA4イベントが送信されないバグを修正](https://github.com/yukihiroyamaguchi569/ict-round/commit/d05e5db)、2026-07-12）。

- **計測開始日（6/17）から7/12までのデータは実質存在しない。** 期間を指定して過去データを見る際は7/12以降に絞ること。
- 7/11に環境感染学会のシンポジウムで発表しており、その反響が7/13（月）以降の新規ユーザー増として現れている。バグ修正のタイミングと重なったのは偶然。

## 現状の実装（`src/analytics.ts`）

計測済みイベント:
- `page_view`（gtag標準、SPAなので実質初回のみ）
- `pwa_install`（method: `standalone_first_launch` / `appinstalled`）
- `pwa_install_banner_click`
- `pwa_install_prompt_result`（outcome）
- `pwa_install_banner_dismiss`

`session_start` / `first_visit` / `user_engagement` はGA4が自動収集するため、追加実装なしで既に計測されている。

## フェーズ2: 「アクティブユーザー」の定義を理解する — 完了 (2026-07-26)

- GA4のアクティブユーザーは単なる訪問者数ではなく、エンゲージメントのあったユーザー。
- エンゲージメントセッションの条件: 10秒以上の滞在 / キーイベント発生 / 2回以上のページビュー のいずれか。
- めぐる君はSPAでページビューが実質1回のみなので、**滞在10秒が実質的な判定基準**になる点を理解しておく。
- `user_engagement` イベントはタブが閉じる瞬間だけでなく、非表示化時・約10秒おきの定期送信・離脱時（`sendBeacon`）の複数タイミングで送信される。ただしオフラインだとどのタイミングでも送信できず欠測する点は変わらない。
- **DAU/MAU比**はGA4に専用カードがなく、「ユーザーのアクティビティの推移」グラフ（レポートのスナップショット）の1日/30日の数値から自分で計算する。
  - 2026-07-26時点: 1日=10, 7日=128, 30日=364 → DAU/MAU ≈ 2.7%。ラウンド業務は毎日行うものではないため、この低さ自体は問題ではない。
  - 30日線は移動窓の性質上、学会由来の7月前半の高アクセスをまだ含んでおり右肩上がりに見える。**8月中旬ごろにその山が窓から外れ、自然に下降に転じる見込み**（異常ではない）。

## 実装済みの追加計測: `display_mode`

インストール版（PWA）からの起動か、ブラウザからの起動かを切り分けて記録する（`src/analytics.ts` で実装済み）。

- `gtag('set', 'user_properties', ...)` でユーザープロパティ `display_mode: 'standalone' | 'browser'` を送信。
- 「アクティブユーザーのうち何%がインストール版か」をレポートで切り分けられる。
- **解釈の注意**: これで分かるのはインストール版の利用割合であり、そのセッションがオフラインだったかどうかは分からない。オフライン利用そのものの指標ではなく、インストールの定着度を見る指標として扱う。
- **レポートで使うにはカスタムディメンション登録が必須**（下記「次のアクション」参照）。登録前に収集されたデータは遡って参照できない。

あわせて、開発時のみ `debug_mode` を有効にしている。PWAをDockやホーム画面から起動した場合はChrome拡張のデバッグモードが効かず、GA4のDebugViewに何も表示されないため。本番ビルドでは除去される。
